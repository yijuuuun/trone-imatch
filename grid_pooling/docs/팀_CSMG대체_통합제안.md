## 1. 네 실험 한눈에 보기

| 담당 | 바꾼 부분 | 학습 규모 | 평가 도시 | 핵심 결과 |
| --- | --- | --- | --- | --- |
| **주희윤 (P2B CorrMatchNet)** | CSMG + PSG + CA + 회귀 헤드 → 공간 상관 매칭 헤드 (0.45 M) | 90K | **빠진 도시 + 미학습 5개 도시** | 미학습 도시 1 km 항법 **96.5~99.4%**, 2D MLE 0.32~0.43 m, 12.5 ms/프레임 |

## 2. 결과를 읽을 때 주의할 점

**(1) 평가 도시에 따라 결론이 뒤집힌다.**
이준 실험에서 같은 설정으로 학습한 두 모델을 비교했다.

| | 학습 도시 검증 MLE | 미학습 도시 1 km 항법 |
| --- | --- | --- |
| CSMG 재학습 | **7.7 m** (더 좋음) | 23.1% (더 나쁨) |
| Grid Pooling | 18.6 m | **41.3%** |

CSMG는 학습 도시의 모습을 외워서 학습 도시에서는 가장 좋아 보이지만, 처음 보는 도시에서는 가장 나쁘다. 학습 없는 진단(타일 맞히기)에서도 CSMG는 Tokyo 85.5%에서 NY 59.0%로 떨어졌다. 그러니 **학습 도시로 평가하면 어떤 대체안도 CSMG보다 나빠 보일 수 있다.** 공식 테스트 분할은 테스트 블록이 학습에 들어 있어(누수) 이 경향이 더 강해진다.

**(2) 데이터가 적으면 아직 학습이 안 된 상태일 수 있다.**
위치를 블록 한가운데로 찍기만 해도 MLE가 약 24.5 m 나온다. 방향을 무작위로 찍으면 MHE 평균이 90°다. MLE가 약 25 m이고 MHE가 85~98°라면 **두 모델 모두 아직 위치와 방향을 배우지 못한 단계**라서, 이 숫자로는 어느 쪽이 낫다고 말하기 어렵다. Train 720~1000개는 90K의 1% 수준이다.

**(3) 비교 조건이 서로 다르다.**
데이터 수, epoch, 손실 함수(MSE 대 SmoothL1), 평가 지표(MLE 대 항법 성공률), 평가 도시가 사람마다 달라서 지금은 네 결과를 한 표에 놓을 수 없다.

## 3. 네 실험을 묶는 이야기 (팀 결론 제안)

### 숨은 문제
CSMG는 특징 지도를 4개 클러스터로 요약하면서 ① **"어디에 있는지"를 잃고**, ② **학습 도시의 모습을 외운다.**
- 근거: 이준 진단(학습 없음, NY 타일 맞히기 CSMG 59% 대 요약하지 않는 dense 96%), 희윤 모듈 진단, 이준 재학습 대조 실험(학습 도시 7.7 m 대 미학습 도시 23.1%)

### 해결: 공간 정보를 남길수록 미학습 도시에서 좋아진다

| 공간 정보 | 방법 | 담당 | 미학습 도시 1 km 항법 |
| --- | --- | --- | --- |
| 없음 (전역 요약) | CSMG (재학습) | 이준 대조군 | 23.1% |
| 거칠게 (4×4 격자) | Grid Pooling | 이준 | 41.3% |
| 전부 (공간 상관) | P2B CorrMatchNet | 주희윤 | 96.5~99.4% |

이준의 풀링 해상도 실험(dense 매칭을 s배 풀링)도 같은 방향이다. 거칠게 풀링할수록 주간 성공률이 떨어졌다(s=1 100% → s=8 43.8% → s=22 12.5%).
※ P2B는 희윤의 자체 평가(미학습 5개 도시)이고, 나머지는 이준의 평가(NY, Paris, London)라서 궤적 세트가 다르다. 같은 틀로 다시 재면 더 깔끔하다(4절).

### 남은 문제: 어두운 조건
- Grid는 어두운 조건(L2)을 개선하지 못했다. VGG 특징 자체가 어두운 영상에서 무너지는 것으로 보인다(이준 대체 백본 실험).
- 희윤의 P2Bv2(저조도 데이터 50%로 학습)가 진행 중이다.
- **강지민의 멀티스케일 어텐션**은 이 단계에서 의미가 있을 수 있다. 어두운 영상에서 지역 패턴(3×3)과 넓은 지형(5×5)을 함께 보는 마스크가 노이즈를 거를 수 있는지 P2B 앞단에서 시험해 볼 만하다(가설).
- **김재홍의 Residual CNN**도 같은 위치(VGG 뒤, 매칭 앞의 adapter)에 넣어 비교할 수 있다.

## 4. 공통 평가 틀 제안

네 명의 aggregator를 **같은 데이터, 같은 설정, 같은 평가**로 비교하자. 이준의 학습·평가 코드를 그대로 쓰면 모듈 클래스 하나만 추가하면 된다.

### 공통 조건

| 항목 | 값 |
| --- | --- |
| 데이터 | `c4m_254k_96bc_b15_s100` 90K 전체 (학습 도시 4곳), 95% 학습 / 5% 검증 |
| 고정 | VGG16 (freeze), 나머지는 같은 시드로 새로 초기화 |
| 학습 | 4 epoch, batch 64, AdamW lr 3e-4 cosine, SmoothL1 (위치 0.8 + 방향 0.2) |
| **대조군** | 같은 설정으로 재학습한 CSMG (이미 있음, 공유 가능) |
| 평가 1 | 학습 도시 검증 MLE |
| **평가 2 (주 지표)** | **미학습 도시 1 km 닫힌 루프 항법** (NY 96 + Paris 32 + London 32궤적, 시드 2026), 같은 궤적 McNemar |
| 평가 3 | NY 어두움 L2 항법 |

### 모듈 추가 방법
`code/swap_lib.py`에 클래스를 넣고 `build()`에 이름을 등록한다. 입력은 VGG conv4_3 `[B,512,32,32]`이고, 반환 형식은 CSMG와 같다.

```python
class MyAggregator(nn.Module):
    def forward(self, x):               # x: [B,512,32,32]
        d = ...                         # [B,1024], L2 정규화 권장
        return None, None, d, None      # CSMG와 같은 반환 형식 (3번째가 descriptor)

# build() 안
if variant == 'my_agg':
    m.csmg = MyAggregator().to(DEV)
```

실행 (Colab T4, 가벼운 모듈 기준 학습 약 30분, 평가 약 15분):
```
python3 train_swap.py my_agg 4
python3 eval_swap.py my_agg
```

※ 희윤의 P2B는 뒷단까지 바꾼 구조라서 이 틀에 그대로 들어가지 않는다. 평가 2(같은 궤적 세트의 항법)만 맞춰 주면 한 표에 놓을 수 있다.
