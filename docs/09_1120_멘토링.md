# 1120 멘토링

팀 Trone (김이준, 김재홍, 주희윤, 강지민) · 2026-11-20 · 마감 11/30

지금까지 한 실험을 배경 → 문제 정의 → 선행 연구의 문제점 → 제안 방법 → 평가 → 분석 → 트레이드오프 → 남은 일 순서로 정리했다. 숫자의 출처는 각 절에 링크한 실험 README다.

## 한 줄 요약

**드론 사진과 위성 지도를 학습 없이 대응점 매칭(LoMa)으로 맞추고, 대응점 수(inlier)를 신뢰도로 써서 "자신 없으면 믿지 않는" 규칙을 넣었다. 처음 보는 도시와 실제 비행(UAV-VisLoc)의 약 1 km 항법에서 기존 모델 6종(Bearing-UAV 포함)과 추측 항법보다 유의하게 많이 도착한다. 대가는 시간(걸음당 0.5~2.3초, 기존 모델 0.01~0.09초)이다.**

---

## 1. 배경

- GPS를 쓸 수 없는 상황(전파 방해, 신호 차단)에서 드론은 카메라로 자기 위치를 알아내야 한다. 드론이 내려다본 사진을 미리 실어 둔 위성 지도와 맞춰 위치와 진행 방향(heading)을 구하는 것이 **시각 기반 위치 추정(visual localization)**이다.
- 출발점은 [Bearing-UAV](https://arxiv.org/html/2603.22153) (CVPR 2026) 논문과 데이터셋이다.
  - 도시 4곳(도쿄·타이베이·싱가포르·SF), 도시마다 위성 지도(약 1 km², 0.25 m/px)와 드론 높이 3D 렌더 22,500장(정답 위치·방향 포함).
  - 모델은 드론 사진 + 지도 타일을 넣으면 좌표와 heading을 바로 회귀한다(VGG16 → CSMG 요약 → 회귀 헤드, 17 M 파라미터, T4에서 장당 약 0.08초).
- 조건: **나침반 없이 영상만** 쓴다(교수님 10/15 피드백). 연산량은 우선순위가 낮고, 저조도보다 **처음 보는 환경에서의 일반화**가 더 중요하다.

## 2. 문제 정의

**입력**: 드론 사진 1장(방향 모름) + 드론이 있다고 믿는 위치 주변의 위성 지도 블록(128 m 정사각형).
**출력**: 블록 안 위치 (x, y)와 heading, 그리고 그 답을 믿어도 되는지.

두 수준에서 푼다.

| 수준 | 질문 | 성공 기준 |
| --- | --- | --- |
| 사진 한 장 | 이 사진은 블록 안 어디인가 | 10 / 20 m 이내 비율 (원 논문은 15 m) |
| 연속 비행(항법) | 사진을 계속 찍으며 약 1 km를 날 때 목표에 도착하는가 | 3D: 도착 시 실제 위치 40 m 이내. VisLoc: 구간 끝 위치 20 / 40 m 이내 |

항법에서 어려운 점은 **오류 누적**이다. 한 번 틀린 위치를 믿으면 다음 걸음에 엉뚱한 지도 블록을 꺼내고, 그러면 다시는 맞출 수 없다. 그래서 "정확한 답"뿐 아니라 **"틀린 답을 알아채는 것"**이 문제의 핵심이다.

추가 제약
- 처음 보는 도시에서 동작해야 한다(시험 도시는 학습·설정에 쓰지 않음).
- 실제 1 km 연속 비행 데이터는 없다. 3D 렌더 시뮬레이터(우리가 만듦)와 UAV-VisLoc 실제 비행 구간(600~1,000 m)으로 보완한다.
- 드론에서 실시간이어야 한다(다음 사진이 오기 전에 계산이 끝나야 함).

## 3. 선행 연구의 문제점

### 3.1 Bearing-UAV (원 모델)

진단과 누수 없는 재학습으로 원인을 모듈 단위까지 좁혔다([01_재설계계획.md](01_재설계계획.md) 1~2장).

| 문제 | 근거 |
| --- | --- |
| **평가 누수**: 공식 테스트 블록·타일이 100% 학습에 들어 있다 | 공개 가중치 3D 오차 4~5 m → 시험 도시를 학습에서 빼고 재학습(B1)하면 20.6 / 21.6 m (블록 가운데만 찍어도 약 24 m) |
| **위치를 외운다**: 요약 단계(CSMG)에서 "어디에 무엇이 있는지"가 사라지고, 회귀 헤드가 학습 도시 좌표를 외운다 | 요약 없이 VGG 특징을 직접 비교하면 타일 96~98%, CSMG 뒤 59%. 처음 보는 도시 10 m 이내 15.8% / 15.2% |
| **방향을 외운다** | 처음 보는 도시 heading 평균 오차 90° / 117° (무작위 수준). 지도를 돌려도 출력이 따라가지 않음 |
| **틀려도 모른다**: 신뢰도 출력이 없다 | 항법에서 틀린 답을 그대로 믿어 지도 밖으로 나감 (4.3절) |
| **한 장까지만 다룬다** | 장거리 항법·오류 처리는 논문 범위 밖 |

### 3.2 그 밖의 방법

| 방법 | 형태 | 문제 |
| --- | --- | --- |
| B2, CorrMatchNet (우리 팀 이전안) | VGG 특징 상관 → 최대점 1개 | 대응점을 찾고 검증하는 단계가 없다. 틀렸는지 확인할 수 없다 |
| OS-FPI | 위치 회귀(heatmap) | 저고도(80~100 m, UL14) 학습. 실제 고고도 사진에 일반화되지 않음 |
| Sample4Geo, MEAN, Game4Loc | 검색형(같은 곳인가만 판단) | 블록 안 좌표를 내지 않아 타일 단위로만 구분. 학습 데이터(University-1652, 게임 렌더)가 실제 고고도 사진과 다름 |
| GeoAnchor | LoFTR + 파티클 필터 | IMU 나침반, 원본 해상도 사진 필요. 우리 조건(나침반 없음)으로 맞추면 매칭이 거의 통과하지 않아 비교에서 뺌 |

공통점: **점수(신뢰도)가 맞는 답을 가려내지 못하거나 아예 없다.** 그래서 항법에서 오류가 누적된다(7.3절에서 실측).

## 4. 제안 방법 (v1)

### 4.1 아이디어

"이렇게 생긴 사진이면 답은 여기"를 **외우는** 대신, 두 영상에서 **같은 점을 찾아 검증하고 기하로 계산**한다. 계산식은 도시가 바뀌어도 같으므로 새 환경에서 덜 무너진다. 검증에서 남은 대응점 수(inlier)가 그대로 **신뢰도**가 된다.

### 4.2 구조

```
[한 장]
드론 사진 ─① 회전 4방향 (0/90/180/270°, inlier ≥ 15면 멈춤)─┐
                                                             ├─②③ LoMa 매칭 ─④ MAGSAC++ ─⑤ 호모그래피 → (x, y), heading
지도 블록 ─ 특징 미리 계산(캐시) ────────────────────────────┘                    │
                                                                    inlier 수 = 신뢰도
                                                                         │
[항법]                                        inlier ≥ 15 → 믿고 위치 갱신
                                              inlier < 15 → "모름" → 추측 항법(직전 위치 + 명령 이동) ······ R1 (예방)
                                                             └ 바로 십자 5블록 재매칭,
                                                               5걸음 연속 "모름"이면 3×3 9블록 (inlier ≥ 20만 채택) ·· R4 (복구)
                                              → 믿는 위치로 다음 지도 블록 선택 → 목표 쪽으로 이동
```

| 단계 | 하는 일 | 가져온 것 / 우리가 만든 것 |
| --- | --- | --- |
| ① 회전 탐색 | 나침반 없이 드론 사진을 4방향으로 돌려 시도. inlier ≥ 15가 나오면 멈춤 | 4방향·멈추기 규칙은 우리가 개발용 데이터로 정함 |
| ②③ 매칭 | LoMa(DaD 검출 + DINOv2 기술자 + 트랜스포머 짝짓기). 대응점 수백~수천 개 | 공개 사전학습 가중치 그대로 (학습 없음) |
| ④ 검증 | MAGSAC++로 틀린 짝 제거 | 표준 기법 |
| ⑤ 위치·heading | 호모그래피로 드론 중심을 지도에 옮김, 회전 성분이 heading | 계산값 (학습값 아님) |
| 신뢰도 "모름" | inlier < 15면 답을 버림. 15는 학습 도시에서만 정함 | 우리 |
| R1 / R4 | 예방(추측 항법으로 버팀) + 복구(이웃 블록 재매칭) | 우리 |
| 지도 특징 캐시 | 지도 블록 특징을 한 번만 계산, 결과 동일 | 우리 (교수님 피드백 10) |
| 항법 시뮬레이터·재생 | 3D 1 km 시뮬레이터, VisLoc 실제 비행 재생 | 우리 |

**숫자 15는 한 번 정해 세 군데(한 장 "모름", 항법 R1, 회전 멈추기)에 그대로 쓴다.** 학습 도시에서 틀린 답의 83%를 걸러 내면서 맞는 답을 적게 버리는 꺾이는 지점이다([05_교수님_보고_1113.md](05_교수님_보고_1113.md) 4.2b).

## 5. 평가 방법

### 5.1 데이터

| 데이터 | 역할 | 쓰는 곳 |
| --- | --- | --- |
| Bearing-UAV 학습 도시 (도쿄·타이베이) | **개발용** | 규칙(15, 4방향, R4) 정하기 |
| Bearing-UAV 시험 도시 (SF·싱가포르) 3D | 시험용 | 한 장 1,000장, 항법 96궤적 × 100 m / 300 m / 1 km |
| UAV-VisLoc `single_calib` 513장 | **개발용** | 실제 사진에서 설정 확인, 기존 모델 기준값 고르기 |
| UAV-VisLoc `single_eval` 1,738장 | 시험용 (한 장) | 모든 모델 한 장 비교 |
| UAV-VisLoc `seq_eval` 92구간 (1,020걸음, 600~1,000 m) | 시험용 (항법) | 모든 모델 실제 비행 비교 |

**원칙**: 설정은 개발용에서만 정하고, 시험용은 확정된 v1로 **한 번만** 돌린다. 결과를 보고 v1을 바꾸지 않았다.

### 5.2 비교 대상

- **추측 항법(dr)**: 사진을 안 쓰고 명령한 이동량만 누적. 이동에는 오차를 넣는다(방향 치우침 3°, 걸음마다 2°, 거리 5%).
- **Bearing-UAV**: B1(시험 도시를 학습에서 뺀 재학습, 공정한 기준선), 원 공개 가중치(시험 도시를 학습 때 봄, 우리에게 불리한 비교).
- **기존 오픈소스 6종**: CorrMatchNet, OS-FPI, Sample4Geo, MEAN, Game4Loc (+ Bearing-UAV). 같은 블록 규칙·같은 4방향 탐색을 붙여 우리 항법에 그대로 꽂음.
- **기존 모델 + R1**: 기존 모델에도 각자의 점수(conf, heatmap, 유사도)로 "모름"을 붙임. 기준은 개발용에서 고름.
- **우리 내부 비교**: LoMa R0(항상 믿음) / R1 / v1(R1 + R4).

### 5.3 지표와 검정

- 한 장: 10 / 20 / 32 m 이내 비율, 원 논문 기준 15 m 이내(LSR@15)와 평균 오차.
- 항법: 도착률(40 m), 구간 끝 20 m 이내(원 논문 SR@20), 걸음 오차, 마지막 오차, "모름" 비율, 걸음당 시간(Kaggle T4).
- 같은 샘플·같은 궤적끼리 짝지어 **McNemar 검정**(성공/실패), 오차는 Wilcoxon.

## 7. 분석

1. **차이를 만드는 것은 매처보다 "모름" 처리(R1)다.**
   LoMa도 항상 믿으면(R0) VisLoc 40 m 이내 41로 Bearing-UAV(41)와 똑같다. R1을 넣으면 69(28 / 0, p = 7e-09)가 된다.

2. **그런데 "모름" 처리를 아무 모델에나 붙인다고 되는 것은 아니다. inlier 수가 좋은 신뢰도라서 된다.**
   기존 모델에 각자의 점수로 R1을 붙이면 추측 항법 수준(40 m 35~55)까지만 오른다. 받아들인 답의 오차 중앙값이 기존 모델 32~61 m, LoMa 20.0 m다. 개발용에서 기존 모델 점수로 거르면 블록 가운데만 찍는 것(28.8%)과 비슷한 27~29%가 한계다. → **우리 방법의 핵심은 "기하 검증에서 나온 inlier 수가 맞는 답을 가려낸다"는 점이다.**

3. **v1의 오차는 거리가 늘어도 커지지 않는다.**
   추측 항법은 거리에 비례해 쌓이고(3D 4.6 → 38 m), v1은 거의 일정하다(2.4 → 3.5 m). 그래서 장거리일수록 v1이 필요하다.

4. **짧은 거리에서는 추측 항법이 오히려 낫다.**
   VisLoc 100 m·300 m에서 추측 항법이 v1보다 유의하게 정확하다(92 vs 84, 88 vs 79). 3D 싱가포르 100 m도 같은 경향(96 vs 93, 유의하지 않음)이다. 출발 위치를 GPS로 주므로 처음 몇 걸음은 추측이 거의 정답이고, 이때 틀린 매칭 한 번(inlier ≥ 15인데 틀림)은 손해만 된다. VisLoc은 GPS 라벨 어긋남(10~16 m)이 매칭에만 오차로 잡혀 이 경향이 더 뚜렷하다.

5. **처음 보는 도시인지가 기존 모델 결과를 크게 바꾼다.**
   3D 100 m에서 원 Bearing-UAV(본 도시)는 걸음 10 m 이내 86~89%, B1(안 본 도시)은 5%다. 우리는 학습하지 않으므로 이 차이가 없다. 원 Bearing-UAV도 1 km에서는 "모름"이 없어 한 번 크게 틀리면 지도 밖으로 나간다(SF 43, 싱가포르 64 vs v1 96, 92).

6. **복구(R4)의 효과는 작다.**
   3D SF는 "모름"이 0%라 R4가 한 번도 돌지 않았다. 싱가포르 1 km 92 vs 90(p = 0.69), VisLoc 72 vs 69(p = 0.25)로 방향은 맞지만 유의하지 않다. 교수님 말씀대로 R4가 못 살린 경우는 장면 자체가 지도와 다른 데이터 문제였다(도쿄 실패 궤적 54걸음 연속 "모름").

7. **4방향이면 충분하다.** 학습 도시, VisLoc 개발용, 3D 시험 도시 모두 8방향과 정확도 차이가 없고(8방향이 더 살린 궤적 0), 시간은 1.5~3배 줄었다. SF는 거의 모든 걸음이 첫 방향에서 멈춘다.

8. **한 장 정확도의 남은 실패는 매칭 기법으로 못 고친다.** 싱가포르 실패는 공사·지붕 변화, 고층 원근, 숲처럼 지도와 장면이 다른 경우다. 회전 16방향, 확대, 다른 매처 재시도, 후보 선택기 모두 효과가 없었다(p ≥ 0.24). 그래서 한 장을 고치는 대신 항법에서 틀린 답에 대처하는 쪽으로 방향을 바꿨다.

### 9.2 결과에서 나온 숙제

1. **짧은 거리에서 추측 항법에 지는 문제.** 출발 직후 틀린 매칭을 믿는 경우다. 예: 추측 위치와 너무 먼 답은 거르기(R2와 비슷, 학습 도시에서는 효과 없었음), 거리에 따라 기준을 바꾸기. 바꾸려면 개발용에서 다시 정해야 하고, 마감 전에 할지 결정이 필요하다.
2. **R4를 최종에 남길지.** 효과가 유의하지 않고(3구간), 실시간 여유를 넘는다. "3×3 뒤 다시 5걸음 기다리기"나 비동기 처리로 시간을 줄일 수 있지만 시험하지 않았다.
3. **"모름" 비율이 높다(VisLoc 49%).** 실제 사진에서 매칭이 절반만 통과한다. 원인(해상도, 계절, 고도 차이, GPS 어긋남) 분석이 아직 없다.
4. **UAV-VisLoc GPS 라벨 어긋남(10~16 m)을 보정하지 않았다.** 10 m 기준이 모든 방법에 낮게 나온다. 원인 규명할지 한계로 명시할지.
5. **속도 추가 단축**(정확도가 바뀌는 것): 키포인트 2048 → 1024, LoMa-B128, `torch.compile`, TensorRT. 결과가 바뀌는 것은 개발용에서 다시 정해야 한다. 젯슨 실측도 없다.
   - DINOv2 MLP 구조적 가지치기(추가 학습 없음)는 해 봤다([results/r1-pruning-4dir](../results/r1-pruning-4dir/README.md), #57). 파라미터는 15~30% 줄었지만 매칭 한 번 시간이 늘고 탐색 방향 수도 늘어(2.59 → 3.05~3.13) 전체 시간이 9~16% **늘었다**. 속도 수단으로는 효과가 없다.
6. **통계적 힘.** 시드 1개, VisLoc 92구간이라 1~3구간 차이(v1 vs R1, 짧은 거리)는 구분이 안 된다.

### 9.3 정리·마감 작업 (~11/30)

- 기존 모델 + R1 비교(`visloc-nav-baselines-r1`) PR 머지.
- 한 장 비교표 통일: 재홍 표의 "이전 측정" 우리 행을 v1 규칙(모름이면 블록 가운데) 결과로 교체, 채점 규칙을 보고서에 명시.
- 실험 동결 → 최종 보고서·발표. 정확도-시간 트레이드오프 그래프(피드백 9).

### 9.4 멘토님께 여쭤볼 것

1. 우리 기여를 **"inlier 기반 신뢰도로 오류 누적을 막는 학습 없는 항법"**으로 내세워도 충분한지. 부품(LoMa, MAGSAC++, 호모그래피)은 모두 기존 것이다.
2. 남은 2주에 **파인튜닝 기준선, 프레임 간 매칭, 저조도** 중 무엇을 우선해야 하는지.
3. 짧은 거리에서 추측 항법보다 못한 결과를 어떻게 보고할지(한계로 둘지, 규칙을 보완할지).
4. 속도(R1 0.54초, v1 2.32초 vs 원 모델 0.05~0.09초)를 더 줄여야 하는지, "R1은 실시간 여유 안"으로 충분한지. 젯슨 수치를 추정으로 보고해도 되는지.
