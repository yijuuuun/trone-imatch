# 프로젝트 스토리와 우리 기여 (2026-10-15 정리)

> **2026-10-16: 이 내용은 [01_재설계계획.md](../01_재설계계획.md) 7장(우리 기여)과 9장(교수님 확인)으로 통합됐다. 최신본은 그쪽을 본다.** 아래는 10-15 당시 기록이다.

이미지 매칭 방향으로 바꾼 뒤, 졸업프로젝트로서 "오픈소스를 가져다 붙였다"에서 끝나지 않으려면 무엇이 우리 기여인지 정리한 문서다. 관련 문서: [00_교수님_피드백.md](../00_교수님_피드백.md), [02_실험기록.md](../02_실험기록.md).

## 1. 고민

- 매칭(같은 점 찾기)은 오픈소스 매처(SIFT-LightGlue, LoMa, RoMa v2 등)를 학습 없이 그대로 쓴다.
- 그것만 하면 졸업프로젝트로서 부족해 보일 수 있다.

## 2. 그래도 방향이 괜찮은 이유

- **교수님이 직접 요구한 방식이다.** 직접 만들지 말고, 서브문제를 푸는 기존 연구를 가져와 적용하라고 하셨다.
- **졸업프로젝트의 기준은 새 알고리즘 발명이 아니다.** 문제 정의, 설계, 구현, 검증을 제대로 했는지가 기준이다.
- **이미 우리만의 분석이 있다.**
    - 원 모델(Bearing-UAV) 실패 원인 진단: 위치 정보가 CSMG 요약 단계에서 사라지고, 회귀 헤드가 좌표를 외운다.
    - 2D 테스트는 드론 영상이 위성 사진을 잘라 돌린 것이라 고전 SIFT로도 0.3 m, 100%가 나온다. 즉 2D 결과(T1 2D, T2, T5)는 매칭 능력의 근거가 되지 못한다. 원 논문과 우리 기존 결과의 해석을 바꾸는 발견이다.
    - 같은 샘플, 같은 규칙, 통계 검정(McNemar, 부트스트랩)으로 하는 공정한 비교 체계

## 3. 오픈소스가 해 주는 것과 우리가 하는 것

| 구분 | 내용 |
| --- | --- |
| 오픈소스 | 사진 두 장 사이의 대응점 찾기(매처), 틀린 짝 거르기(MAGSAC++) |
| 우리 | 문제 분할, 서브문제별 도구 선택·연결, 위치·heading 계산, 공정한 평가, **약한 서브문제 보완**, **장거리 항법 시스템 통합** |

## 4. 기여를 채울 세 가지

### 4.1 약한 서브문제를 직접 보완 (핵심)

오픈소스가 무너지는 조건을 찾고, 그 부분만 우리가 고친다. 현재 후보는 3D Singapore다. 고전 SIFT의 10 m 이내 비율이 19%로, B2(69%)에 크게 진다.

- 회전·축척을 매칭 전에 맞추는 작은 모듈을 우리 데이터로 학습한다. [AeroMap3D](https://arxiv.org/html/2607.14009v1)에서 고정된 RoMa v2의 등록 성공률을 62.4%에서 99.2%로 올린 방식이다.
- 건물 원근(3D) 때문에 생기는 오차를 줄이는 방법을 찾아 적용한다.
- 목표는 "오픈소스 그대로 X% → 우리 보완 후 Y%"를 같은 샘플과 통계 검정으로 보이는 것이다.

### 4.2 장거리 항법 시스템으로 통합

매처는 사진 두 장만 맞춘다. 실제 항법에는 다음이 더 필요하고, 이건 오픈소스에 없다.

- inlier 수로 이번 추정을 믿을지 판단한다 (신뢰도)
- 틀렸을 때 후보 블록 여러 개를 다시 매칭해서 복구한다 (Top-N 재선택, [AnyVisLoc](https://arxiv.org/html/2503.10692v2))
- 이전 프레임 위치로 탐색 범위를 줄인다

원래 계획한 Phase 3(무너지는 조건에서의 복구)와 바로 이어진다. 평가는 1 km 폐루프 항법이며, 3D 또는 실제에 가까운 조건으로 해야 한다(2D는 너무 쉬움).

### 4.3 체계적인 벤치마크

여러 매처를 같은 조건에서 비교하고, 어떤 조건에서 어떤 매처가 왜 무너지는지 분석한다. 보고서의 한 장이 된다.

## 5. 최종 스토리

1. **문제 정의와 진단**: 원 모델은 처음 보는 도시에서 왜 실패하나
2. **서브문제 분할**: 회전 · 매칭 · 검증 · 위치/heading 계산 · 블록 선택
3. **서브문제별 기존 기술 비교**: 오픈소스 매처 벤치마크, 2D 테스트의 한계 발견
4. **약한 서브문제 보완**: 우리 데이터로 학습한 보완 모듈 (4.1)
5. **시스템 통합과 검증**: 신뢰도 + 복구가 들어간 장거리 항법 (4.2)

한 줄로: "오픈소스를 붙였다"가 아니라 **"검증된 부품으로 시스템을 설계하고, 부족한 부분을 직접 해결했다."**
