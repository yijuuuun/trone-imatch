# 교수님 피드백과 팀 결정 (2026-11-13)

[05_교수님_보고_1113.md](05_교수님_보고_1113.md)로 보고한 뒤 받은 피드백과, 같은 날 팀 회의에서 정한 할 일·분담. 마감 11/30.

## 요약

- **단거리부터 입증하고 장거리로 넘어간다.** 지금은 한 장(1,000장)과 1 km 항법만 있고 그 사이가 비어 있다.
- **기준선을 "동작하는 것"으로 바꾼다.** B1(원 Bearing-UAV, 15%)이 허수아비처럼 보인다. 사전학습 그대로 → 파인튜닝 순서로 다시 돌리고, 다른 오픈소스 방법도 같은 데이터로 돌린다.
- **새 데이터셋은 UAV-VisLoc.** 같은 데이터로 원 Bearing-UAV, 우리 방법(R1, R1 + R4), 다른 모델을 모두 돌려 비교한다.
- **헤딩 탐색을 8방향 vs 4방향으로 비교**한다. 둘 다 inlier 15개가 나오면 멈추고, 시간과 정답률을 잰다.
- 추가: 저조도 같은 챌린징한 상황, 연산량 줄이기([06_경량화_제안.md](06_경량화_제안.md)).

## 2. 팀 회의 결정

### 2.1 방향

1. **단거리 → 장거리 순서로 입증.** 단거리 근거 실험을 하나 돌려 "단거리에서 우리 방법이 잘 된다"를 먼저 보이고, 그다음 장거리(1 km)로 넘어간다.
2. **챌린징한 상황**: 저조도 환경.
3. **연산량 줄이기**: [06_경량화_제안.md](06_경량화_제안.md) 방향.

### 2.2 새 데이터셋: UAV-VisLoc

데이터: [UAV-VisLoc](https://github.com/IntelliSensing/UAV-VisLoc) (실제 드론 비행 + 위성 지도).

- 지금까지는 Example 일부(2.4 GB, 시퀀스 03, 260장)만 썼고, 위치가 10 m 이내 15% / 32 m 이내 82%로 좌표 어긋남이 의심되는 상태다([../experiments/2026-11-13_external/README.md](../experiments/2026-11-13_external/README.md)). 이번에는 **새로 받아서 다시 가공**한다.
- 가공한 데이터 하나로 아래 방법을 **모두 같은 표본에서** 돌린다.

| 방법 | 설명 |
| --- | --- |
| 원 Bearing-UAV | 사전학습 가중치 그대로 (기준선) |
| 우리 R1 | v1 예방: inlier < 15이면 "모름" → 추측 항법 |
| 우리 R1 + R4 | 예방 + 복구: 5걸음 연속 "모름"이면 주변 3×3 블록 재탐색 |
| 다른 모델 | 동작하는 오픈소스 방법 (1장 피드백 6·7) |

### 2.3 헤딩 탐색: 8방향 vs 4방향

- 드론 사진을 8방향(45° 간격) 또는 4방향(90° 간격)으로 돌려 보며, **inlier 15개가 나오면 그 자리에서 멈춘다**("멈추기", [05_교수님_보고_1113.md](05_교수님_보고_1113.md) 4.5절).
- 두 설정에서 **걸음(장)당 시간**과 **정답률**을 재고 어느 쪽을 쓸지 정한다.

### 2.4 단거리·장거리 비교 (후속)

R1과 R1 + R4 중 하나로 확정된 뒤, 같은 방법으로 **100 m / 300 m / 1 km** 비행을 비교한다.

## 4. 우선순위 (마감 11/30)

1. **짧은 비행 추가**: 같은 시뮬레이터로 거리만 줄여서(학습 도시). 바로 할 수 있음.
2. **기준선 강화**: B1 사전학습 → 파인튜닝, 동작하는 오픈소스 기준선 1개 이상. 같은 데이터(한 장 1,000장, 1 km 96궤적, UAV-VisLoc).
3. **v1 확정**: R1 + 재매칭(R4 또는 R3), 헤딩 8방향 / 4방향. 확정 후 시험 도시 1 km 한 번.
4. **속도**: 지도 특징 미리 뽑기 → 정확도-시간 트레이드오프 표.
5. **프레임 간 매칭**(오버랩): 시간 되면.
6. **챌린징 상황**(저조도), **학술적 통합**: 여유 있으면.

## 5. 확인할 것

- **"하드한 데이터셋 45%"**가 어떤 데이터·방법·지표의 숫자인지.
- **파인튜닝 범위**: [04_팀분담_일정.md](04_팀분담_일정.md)에서는 C2(우리 매처 미세조정)를 일정 문제로 뺐다. 이번 요청은 **기준선(원 Bearing-UAV)** 파인튜닝이라 대상이 다르지만, GPU 시간을 누가 얼마나 쓸지 정해야 한다.
- **재매칭 방식**: 교수님 말씀("바로")은 R3(즉시 이웃 재매칭)에 가깝다. R4(5걸음 후 3×3)를 유지할지, R3를 추가로 돌릴지.
- **UAV-VisLoc 좌표 문제**: 새로 가공해도 어긋나면, 원인을 더 팔지 한계로 명시할지.
- **학술적 통합**을 할지 팀에서 정하고, 하기로 하면 교수님께 따로 말씀드리기.
