# 회전을 완벽히 맞춰주면? (김이준, 2026-11-02)

## 무엇을

"회전을 맞추게 해야 하지 않나?"를 직접 확인했다. 드론 영상을 **정답 heading으로 미리 돌려** 1방향만 매칭했다(`run.py --oracle-rot`). 회전 추정이 완벽한 경우를 흉내 낸 상한 실험이고, 실제 방법은 아니다(정답을 쓴다).

```bash
python scripts/kaggle/build_kernel.py --user yijuniverse --dataset yijuniverse/im-t1-3d-1000 --slug oracle-rot-sg \
    --args "--matchers loma --oracle-rot --kmin 100 --sets 3d_ho37bc --tag=-oracle"     # SF는 oracle-rot-sf, 3d_ho38bc
python scripts/evaluate.py experiments/2026-11-06_oracle_rotation/loma_oracle_sg.csv --kmin 100
```

돌리는 방향 부호는 SF 40샘플로 먼저 확인했다: +heading으로 돌린 드론 영상 가운데가 정답 위치 지도와 NCC 0.38, 반대 부호는 0.04.

## 결과 (3D, k = 100~999, 도시마다 900샘플)

| 방법 | Singapore 10 m 이내 | SF 10 m 이내 | 1장당 |
| --- | --- | --- | --- |
| 1방향, 회전 안 함 (0°) | 72.9% | 96.0% | 0.29 s |
| **1방향, 정답 heading으로 돌림 (완벽한 회전)** | **73.3%** | **96.4%** | 0.31 s |
| 8방향 (지금 방법) | 75.4% | 96.8% | 2.4 s |
| 16방향 | 76.8% | 96.8% | 5.2 s |

짝지은 검정: 완벽한 회전 vs 회전 안 함 = Singapore 47 / 43 (p = 0.75), SF 6 / 2 (p = 0.29). 완벽한 회전 vs 8방향 = Singapore 35 / 54 (p = 0.056).

## 결론

- **회전을 완벽히 맞춰줘도 거의 안 오른다 (72.9% → 73.3%, 차이 없음).** LoMa는 영상이 돌아가 있어도 매칭을 해낸다. 따라서 heading을 미리 추정하는 모듈(AeroMap3D식 yaw 추정)을 만들어도 이득이 없다. 회전은 병목이 아니다.
- **8방향·16방향이 더 좋은 이유는 회전을 맞춰서가 아니라 "여러 번 시도"하기 때문이다.** 같은 영상을 다르게 돌리면 다른 짝이 잡히고, 그중 하나가 맞을 기회가 늘어난다. 완벽한 회전 1번(73.3%)보다 대충 돌린 8번(75.4%)이 낫다.
- 그러므로 Singapore를 올리는 길은 (1) 여러 시도 중 맞는 걸 고르는 것(C3 감지기, 상한 88.3%)과 (2) 짝 자체가 안 잡히는 샘플을 매칭 쪽에서 고치는 것(배율, 매처 교체, 블록 선택)이다. 회전 추정 개선은 하지 않는다.
- 회전 오류 태그가 붙은 실패도 원인은 짝 부족이다(inlier 중앙값 9개). 매칭이 실패해서 회전도 틀린 것이다.
