# UAV-VisLoc 재생 항법: R1, R1 + R4 (분담 3·4번, 김이준)

[docs/07](../../docs/07_교수님_피드백_1113.md) 분담 3번(R1), 4번(R1 + R4). 데이터는 [2026-11-13_visloc_data](../2026-11-13_visloc_data/README.md)의 `seq_eval`.

**결정 (11/15 팀)**: v1 = R1 + R4 (예방 + 복구).

**결론 한 줄**: 실제 비행에서도 R1이 R0보다 크게 낫고(마지막 40 m 이내 42% → 71%, p = 2e-07), R4는 R1 위에 5구간을 더 살린다(71% → 76%, p = 0.06, 잃은 구간 0). 다만 걸음 평균 오차는 추측 항법만(dr)이 더 작다(아래 3장).

## 1. 무엇을

- `seq_eval`: 비행 구간 92개, 걸음 1,020개(출발 걸음 제외). 구간 길이 중앙값 948 m, 걸음 11개, 사진 간격 60~130 m.
- 찍힌 순서대로 재생(`imatch/replay.py`). 추측 위치 주변 블록에서 매칭하고, 추측 항법 이동량 = GPS 이동량 + 시뮬레이터와 같은 오차(`--odo vio`: 방향 치우침 3°, 걸음 2°, 거리 5%).
- 같은 seed라 네 variant 모두 같은 구간·출발점·이동 오차.

| variant | 뜻 |
| --- | --- |
| dr | 매칭 없이 추측 항법만 |
| r0 | 매칭 결과 항상 믿음 (오류 처리 없음, 원 모델과 같은 조건) |
| r1 | inlier < 15면 "모름" → 추측 위치 (v1 예방) |
| r4g0n5w20 | r1 + "모름"이면 그 걸음에서 바로 십자 5블록 재매칭(R3), 5걸음 연속 "모름"이면 3×3 9블록(inlier ≥ 20) (v1 복구, `imatch/nav.py` `Research`) |

## 2. 명령

```bash
python scripts/kaggle/build_kernel.py --user yijuniverse --dataset heeyunju/visloc-seq-eval --slug visloc-nav-r1r4 \
    --script run_visloc_nav --args "--matcher loma --angles 8 --stop-inl 15 --variants dr,r0,r1,r4g0n5w20 --odo vio --seed 2026"
kaggle kernels push -p kaggle_kernels/visloc-nav-r1r4 --accelerator NvidiaTeslaT4
```

Kaggle T4, 전체 약 2시간 44분.

## 4. 해석

- **R1은 R0의 오류 누적을 막는다.** R0은 틀린 매칭을 믿어 64.5% 걸음에서 정답이 고른 블록 밖으로 나간다. 3D 도쿄(34% → 97%)와 같은 모양.
- **R4는 실제 비행에서 처음으로 이득이 보인다.** 5구간을 더 살리고 잃은 구간이 없다(p = 0.06으로 경계). 3D 학습 도시에서는 이득이 없었다. 대신 걸음당 시간이 0.9 → 5.6 s.
- **추측 항법만(dr)이 앞쪽 걸음에서 더 정확하다.** 매칭은 600 m 넘어서야 dr을 앞선다. 이유 두 가지:
  1. 구간이 짧다(걸음 11개). 추측 항법 오차는 거리에 따라 쌓이므로 앞쪽에서는 작다.
  2. **dr은 정답(GPS)과 같은 좌표에서 움직인다.** 이동량을 GPS 차이로 만들었으므로 GPS 라벨의 진행 방향 어긋남(10~16 m, visloc_data 2.2절)이 dr에는 없고 매칭에만 오차로 잡힌다. 받아들인 매칭의 오차 중앙값이 20.1 m인 것과 맞는다. 즉 dr에 유리한 비교다.
- 그래서 이 데이터에서는 **걸음 10 m 비율보다 마지막 오차·마지막 40 m 이내**가 공정한 지표다.

### R4가 얼마나 자주 켜지나 (출발 걸음 제외 1,020걸음)

| | 걸음 | 비율 | 구간 |
| --- | --- | --- | --- |
| 매칭 믿음 (inlier ≥ 15) | 530 | 52% | |
| "모름" → 재매칭 시도 (십자 또는 3×3) | 490 | 48% | |
| └ 3×3까지 간 걸음 (5걸음 연속 "모름") | 170 | 17% | 36 / 92 |
| 재매칭으로 위치를 되찾음 | 29 | 2.8% | 25 / 92 |
| └ 그중 3×3로 되찾음 | 4 | 0.4% | |

- 복구가 실제로 위치를 고친 걸음은 2.8%뿐이지만, 그 덕에 R1 대비 5구간이 더 성공했다(잃은 구간 0).
- 되찾은 29걸음 중 25걸음은 바로 하는 십자 재매칭이다. 교수님 피드백 1("실패하면 그 주변을 바로 다시 매칭")과 같은 동작.
- 시간: 3×3 걸음(17%)이 전체 시간의 45%를 쓴다(걸음당 19.8 s, 나머지 4.8 s). 경량화(지도 특징 재사용)는 이 부분부터 줄이면 효과가 크다.

## 5. 한계

- 92구간 하나의 seed. R4 vs R1은 p = 0.06.
- "모름"이 48%로 3D(도쿄 학습 도시 수준)보다 훨씬 많다. LoMa가 이 데이터에서 약하다(visloc_data 2.1절, 한 장 10 m 10.7%).
- 실제 사진이라 추정대로 드론을 움직일 수 없다(재생). 3D 1 km "도착 성공"과 직접 비교하지 않는다.
