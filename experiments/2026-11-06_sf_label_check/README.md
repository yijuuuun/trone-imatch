# SF 실패 점검: 대부분 데이터셋 정답 라벨이 틀렸다 (김이준, 2026-11-02)

## 무엇을

SF(샌프란시스코) 실패 34건은 inlier가 많은데도(중앙값 312개, 성공 샘플과 비슷) 위치가 20~60 m, heading이 90° 이상 틀렸다. 매칭은 잘 됐는데 답이 틀린 이상한 경우라서 정답 라벨을 의심했다.

확인 방법(`scripts/check_labels.py`): 드론 영상을 (1) 정답 위치·heading, (2) LoMa 추정 위치·heading으로 지도 블록에 겹쳐서 밝기 상관(NCC)을 잰다. 매처와 무관하게 영상만으로 어느 쪽이 맞는지 본다. 추정 쪽 NCC ≥ 0.5이고 정답 쪽 < 0.2이면 "라벨 의심"으로 표시한다.

```bash
python scripts/check_labels.py results/loma_8dir.csv --data data/im_t1_3d_1000 --out results/label_check_t1_3d.csv
```

## 결과 (3D, k = 0~999)

| | SF 실패 34건 | SF 성공 (60개 표본) | Singapore 실패 | Singapore 성공 (60개 표본) |
| --- | --- | --- | --- | --- |
| NCC 중앙값, 정답 위치 | **0.04** | 0.46 | 0.12 | 0.25 |
| NCC 중앙값, LoMa 추정 위치 | **0.75** | 0.66 | 0.13 | 0.30 |

- SF 실패 34건 중 **28건이 라벨 의심**이다. 추정 위치에서는 영상이 지도와 잘 겹치는데(NCC 0.75, 성공 샘플보다 높음), 정답 위치에서는 전혀 안 겹친다(0.04). 즉 LoMa가 맞고 데이터셋 라벨이 틀렸다.
- 예시 `sf_failures.jpg` (왼쪽 드론 영상, 오른쪽 지도. 초록 = 정답, 빨강 = LoMa): k609는 드론 영상의 횡단보도와 초록 지붕 건물이 빨간 상자 쪽에 있다. 초록 상자(정답)는 빈 땅이다.
- 나머지 6건 중 3건(k41, 89, 380)은 10.3 m로 기준을 살짝 넘긴 것, 2건(k388, 955)은 짝이 거의 없는 진짜 실패다.
- Singapore는 1,000개 중 6건만 의심이다. Singapore 실패는 라벨 문제가 아니라 진짜 매칭 실패다.
- 라벨 의심 샘플은 특정 블록에 몰려 있지 않다(블록 번호가 제각각). 원본 데이터셋의 샘플 단위 오류로 보인다.

## 결론

- **SF는 사실상 다 풀렸다 (99.4%).** 남은 실패는 거의 라벨 오류다. 앞으로 개선 노력은 Singapore에 집중한다.
- 보고서에는 두 숫자를 다 쓴다: 전체(기존 비교 그대로) + 라벨 의심 제외. 순위는 바뀌지 않는다.
- **C3 학습 데이터에도 같은 점검을 건다.** 학습 도시 라벨이 틀리면 "맞는 추정"이 "틀림"으로 라벨링되어 감지기를 망친다. 라벨 의심 샘플은 C3 학습에서 뺀다.
- 이 점검은 C1(진단·공정한 평가) 기여에 추가할 수 있다: 원 논문 데이터셋의 3D 시험 라벨 일부가 틀렸음을 영상으로 확인.
